## 验收口径

1. 未配置 DeepSeek Key 时必须给出可理解的错误，且不得保存空草稿。
2. AI 返回结果必须能被序列化为草稿，并保存修改原因、关键词覆盖和风险提示。
3. 真实性校验必须识别新增邮箱和改动后的数字。
4. 简历版本可以保存排版、检测并发冲突、删除并恢复。
5. 证件照必须校验尺寸；有效照片可读取，过低分辨率照片应被拒绝。
6. PDF 未生成前不能确认定稿；生成后可下载有效 PDF，并能进入 `pdf_confirmed`。
7. 修改或删除通用简历照片后，旧 PDF 必须失效，定制简历回到草稿状态。
8. 工作台、A4 编辑器和数据桥接脚本必须正常加载。
9. 发送/投递范围必须已经移除。
10. 提交不得包含 `.env`、真实简历、照片、数据库、生成 PDF 或其他本地数据。

## 浏览器检查

- 工作台成功显示 5 个有效岗位、3 个未读岗位和 1 个归档岗位。
- 每日岗位列表显示 3 个当日岗位，岗位详情区域和采集操作区可正常渲染。
- A4 编辑器显示“林知夏”虚构简历、教育背景、实习经历、项目经历和技能特长。
- 未绑定照片时，编辑器会发起一次照片请求并收到 `404`；页面主体不受影响，但后续可增加前端条件判断以消除无意义请求。

- `README.md` 明确要求 `.env` 仅保存在本机；`.env.example` 只包含占位值。
- 测试过程中生成的 SQLite 数据库、证件照和 PDF 均位于本地 `data/`，不得提交。
- 本轮 PR 只新增测试记录，不修改已有 `docs/`、`evidence/` 或 `EVIDENCE_INDEX.md`。

## 未覆盖项与残余风险

- 测试环境没有 DeepSeek Key，因此未调用真实外部模型；已验证缺 Key 失败路径，并用结构化测试结果验证草稿保存链路。
- 生产 PDF 渲染函数使用 macOS 字体路径。Windows 测试机在字体加载边界替换为可用中文字体，已验证 PDF 生成、下载、分页和定稿状态；部署目标的 macOS 字体渲染仍需人工打开 PDF 检查一次。
- Chrome Headless 已完成桌面布局冒烟；编辑内容后的视觉细节和系统打印对话框仍需人工检查。
