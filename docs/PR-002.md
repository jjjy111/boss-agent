## Why

Tasks could be created and given due dates, but never closed, so the overdue view kept
nagging about work that was already finished. REQ-002 adds the missing half of the loop:
mark a task done, and stop counting it as late.

## What changed

| Layer | Change | File |
| --- | --- | --- |
| Domain | `done` and `completed_at` fields, `mark_done()` returning a completed copy, `is_overdue()` now ignores completed work | `boss_agent/models.py` |
| Persistence | `TaskStore.resolve()` (exact id or unique prefix) and `TaskStore.complete()`; both keys are read with `.get()`, so older task files still load | `boss_agent/store.py` |
| CLI | `done <task-id>`, `[done]` marker in the list output | `boss_agent/cli.py` |

## Risk and rollback

The only risk is the data format: a `done` key is written from now on. Reading is defensive
(`raw.get`), so an older file loads, and an older version of the tool ignores the extra keys
it does not know. Rollback is a `git revert` of the merge commit; tasks completed in the
meantime simply reappear as overdue, nothing is lost.
